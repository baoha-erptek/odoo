UI/UX Improvement Proposal

Hatafa Etsy ERP · 2026-06-27 · a NEW design exploration — does not modify docs/owner/business-flows. Companion to the mismatch report.

The functional contract is largely delivered. What's missing is presentation and findability: the dashboard dumps 25–34 columns with no summary, work has no board to flow across, and the app is split into two overlapping menus. This proposal closes those gaps with standard Odoo views + reuse of the in-house muk_web_* bundle — minimal custom code, maximum visible polish.

1 · Design principles

  1. Summarise before you enumerate. Every operational screen opens with a KPI band answering "what needs me now?" before the raw table.
  2. One hub, role-aware. Collapse the Etsy + Operations split into a single operational app with a role-scoped sidebar. Each role lands where its work is.
  3. Let work flow on a board. The 17-stage pipeline becomes a kanban; status changes by drag, not by opening a wizard.
  4. Curate, don't truncate. Default views show 8–12 high-signal columns; the full 34-column Excel view stays available as a saved "Excel" filter.
  5. Reuse the brand chrome we already own. muk_web_colors applies #714B67 everywhere; muk_web_appsbar gives the sidebar; muk_web_refresh makes dashboards live.

2 · Current state (what we're fixing)

3 · Proposed: unified, role-aware navigation

Merge the two top-bar apps into one Hatafa Operations hub with a left sidebar (muk_web_appsbar). Eliminates the Design Queue/Design Files and Listing Variants/Listings duplication. Each role's group controls which sections show and which is the landing page.

6 · Proposed: order form & wizard polish

  • Rename the "Gearment" tab to Fulfillment and the button to Request Gearment Quote (match the mockup vocabulary); add a read-only recipient/address block in the quote wizard so the operator confirms where before committing.
  • Status badges everywhere a state lives (widget="badge" + decoration-*) — pipeline stage, design status, tracking-push status — so state reads at a glance.
  • Chatter on the side (muk_web_chatter) on the order form so buyer messages and the conversation sit next to the order, not below the fold.

7 · Reuse vs build (Standard-Odoo-First)

All seven muk_web_* modules already exist in openeducat_erp19/custom_addons/ — Odoo 19, LGPL-3, CE, no Enterprise dependency. Copy them into odoo19_esty/custom_addons/ (or share the addons-path). They close most of the chrome gaps for near-zero custom code.

8 · Suggested rollout order (low risk → high value)

  Wave 1  Reuse chrome      muk_web bundle in addons-path  → brand + sidebar + live refresh   (1-2 days, zero model change)
  Wave 2  Dashboard KPIs    KPI band + saved filters + curated columns                        (2-3 days)
  Wave 3  Pipeline board    kanban grouped by state, drag→_write_pipeline_state                (2-3 days)
  Wave 4  Nav merge         collapse Etsy+Operations into one role-aware menu tree             (2 days)
  Wave 5  Roles + RD dash   group_rd/group_pd + Price-Control view + role landings             (3-4 days)
  Wave 6  Form polish       Fulfillment rename + badges + quote recipient block + side chatter (1-2 days)
Each wave is independently shippable and reversible. Waves 1–3 deliver ~80% of the perceived improvement. None of them touch the functional contract — they re-present what already works.
