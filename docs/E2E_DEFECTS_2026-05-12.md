| Field | Value |
|---|---|
| **Severity** | Medium (blocks E2E Gearment push success on demo data; production grade depends on real product master) |
| **Pipeline stage** | Gearment push payload validation |
| **State** | surfaced → triaged |
| **First observed** | 2026-05-12 13:43 UTC |
| **Reproducer** | After deploying P1-DESIGN-AUTO-CREATE-FROM-EMAIL and creating approved design.file rows for an order's non-shipping lines (e.g. S01363 lines 725, 726), call `sale.order.action_push_to_gearment([1379])`. Vendor returns 400: `data.line_items[0]: Exactly one of 'variant_id' or 'legacy_id' must be set [oneof_variant_id_legacy_id]` (also a misleading second error about printing_options — Gearment validator double-reports when the oneof check fails). |
| **Suspected cause** | `multichannel_hub_fulfillment/services/gearment_payload_builder.py:_safe_int` returns `0` for non-numeric SKUs. Demo product templates seeded with `x_gearment_sku='GMT-DEMO-EMAIL-NNNN'` (templates 13/14/16/17) and `'DEMO-T-18'` (template 18). All non-numeric → all `legacy_id=0` → rejected. |
| **Impact** | (a) Demo Gearment push cannot succeed end-to-end. (b) The "second error" in the vendor response (about location_code) is a misleading artifact of Gearment's validator — it does NOT mean our `printing_options` payload is wrong (we correctly send `[{location_code:'front', url:'...'}]`). Future operators must read the FIRST error to understand the cause; risk of re-running the printing_options chase from memory `feedback_fix_observability_before_chasing_symptoms.md`. |
| **Routing** | (a) **Demo-data fix**: update `deployment/scripts/seed-demo-esty.py` `make_products` to set `x_gearment_sku` to a numeric value (e.g. derived from template ID or a fixed mock catalog ID). Optionally publish a small mapping doc so operators understand what numeric IDs map to which Gearment catalog entries in the sandbox. (b) **Production-grade**: when real Gearment catalog IDs are loaded, this defect disappears. (c) **Defensive UX**: in `_safe_int`, log a warning + post chatter when SKU coerces to 0, so the operator gets a CLEAR signal instead of a 400 round-trip. |
| **Regression test plan** | Phase 2 ORM test: build payload from an order whose product template has non-numeric SKU; assert `legacy_id=0` AND a chatter message ("non-numeric x_gearment_sku") was posted; OR enforce constraint at write time (require numeric `x_gearment_sku`). Phase 1 DB test: assert seed-demo-esty creates products with numeric `x_gearment_sku`. |
| **Owner** | next planner agent |
| **Slice proposal** | `P0-FIX-DEMO-NUMERIC-SKU` (deployment scripts) + optional `P4-01-FIX-NON-NUMERIC-SKU-WARNING` (defensive UX) |
