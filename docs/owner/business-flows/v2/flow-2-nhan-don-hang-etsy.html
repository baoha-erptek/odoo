Tiếp nhận đơn hàng Etsy

BCác bước chi tiết (8 bước)

  • 1
    Khách Etsy
    Khách bấm "Buy Now" trên Etsy
    Khách chọn sản phẩm, nhập thông tin giao hàng (tên, địa chỉ, email), xác nhận thanh toán. Etsy gán mã đơn và ghi nhận tình trạng thanh toán (đã trả / chờ / hoàn lại).
  • 2
    Hệ thống Odoo · mỗi 5 phút
    Cron tự động pull đơn từ Etsy
    Hệ thống chạy lịch tự động 5 phút một lần. Lần đầu: lấy hết các đơn chưa có. Lần sau: chỉ lấy những đơn có thay đổi từ thời điểm cuối cùng (phương thức tăng dần, tiết kiệm dữ liệu). Công suất: 50–100 đơn/ngày, mỗi lần kéo < 5 giây.
    Chi tiết: Lịch tự động chạy cứ 5 phút = 288 lần/ngày. Lần gọi API pull danh sách đơn mới hoặc thay đổi. Nếu lỗi 3 lần liền → tự chuyển sang dự phòng email 10 phút/lần.
  • 3
    Etsy API
    Etsy trả danh sách đơn với chi tiết sản phẩm
    API trả JSON gồm: mã đơn, ID khách, email khách, địa chỉ giao, giá từng sản phẩm, tình trạng thanh toán, thời điểm sửa đơn cuối cùng. Dữ liệu này đủ để bóc tách thông tin đơn hàng vào Odoo.
  • 4
    Hệ thống Odoo
    Bóc tách đơn + ghi nhật ký + kích hoạt dự phòng nếu cần
    Hệ thống đọc dữ liệu từ Etsy, kiểm tra xem đơn này có tồn tại rồi không (bằng mã đơn Etsy). Nếu đơn mới → tạo dòng nhật ký ghi thời điểm, mã shop, kết quả HTTP, số đơn lấy được. Nếu đơn cũ mà trạng thái thay đổi → cập nhật nhật ký. Dự phòng: nếu API lỗi 3 lần liền → alert BA và chuyển sang email.
    Chi tiết: Nhật ký Etsy lưu: thời điểm, mã shop, HTTP status, endpoint gọi, đối tượng nhận, kết quả. Ví dụ: "2026-06-03 14:03 | shop 60752333 | 200 | /orders | 14 đơn | thành công". Email dự phòng chỉ bật khi API hỏng 3 lần → gửi cảnh báo cho BA.
  • 5
    Hệ thống Odoo
    Tìm hoặc tạo khách hàng dựa trên email
    Hệ thống tìm khách hàng theo email từ Etsy. Nếu đúng 1 kết quả → tự liên kết (không cần BA duyệt). Nếu 0 kết quả → tạo khách mới với tên từ Etsy. Nếu nhiều hơn 1 kết quả → BA Lead phải duyệt chọn cái nào qua bảng "Nhật ký email — chưa xử lý".
    Ngoại lệ: Email trống hoặc có ký tự lạ → BA duyệt thủ công qua giao diện "Nhật ký email". Hệ thống dùng tìm kiếm chuẩn Odoo trên mô hình khách hàng, không có wizard riêng.
  • 6
    Hệ thống Odoo
    Tạo đơn hàng với trạng thái + địa chỉ + mốc Etsy
    Hệ thống tạo đơn hàng chứa: khách (từ bước 5), từng dòng sản phẩm (mỗi mặt hàng → 1 dòng), địa chỉ giao (từ Etsy), tình trạng thanh toán (đã trả / chờ), trạng thái = "Mới nhận" (mặc định). Lưu thêm thời điểm Etsy sửa đơn cuối cùng để biết khi nào khách chỉnh sửa.
    Chi tiết: Dòng sản phẩm ghi {sản phẩm, số lượng, đơn giá = giá Etsy ÷ số lượng, nếu có: nội dung cá nhân hoá}. Mốc thời gian Etsy sửa lần cuối — nếu Etsy có cập nhật mà Odoo chưa kéo → lần chạy sau sẽ lấy lại và cập nhật.
  • 7
    Hệ thống Odoo
    Định tuyến: Gearment → Dropship; không → MTO
    Hệ thống kiểm tra từng dòng sản phẩm: nếu có ID giao với Gearment (xưởng in đối tác) → gắn cờ "Dropship", đơn sẽ theo quy trình giao hàng Dropship. Nếu không có → gắn "MTO", đơn sẽ theo quy trình in nội bộ. Một đơn có thể vừa MTO vừa Dropship → hệ thống sẽ tách thành 2 hướng giao riêng.
  • 8
    Hệ thống Odoo · dự phòng
    Khi API hỏng 3 lần liền: chuyển sang email dự phòng
    Nếu Cron API gặp lỗi 3 lần liên tiếp (ví dụ: token hết, quá giới hạn tốc độ, Etsy tạm down) → hệ thống tự chuyển sang chế độ "Email Fallback": Cron đọc email thay vì API, 10 phút một lần. BA được cảnh báo để authorize lại hoặc kiểm tra kết nối. Sau khi sửa → bấm "Test Connection" để quay lại API.
    Lý do hai đường: Email chậm hơn API (có thể trễ vài phút) và định dạng email khó dự đoán → cần parser mạnh. Nhưng nó chạy dưới dạng dự phòng để shop không bị mất đơn khi API tạm down.

DKhử trùng đơn + phạm vi khách hàng

Khử trùng lặp: Hệ thống kiểm tra mã đơn Etsy trước khi tạo. Nếu đã có → bỏ qua; nếu chưa có → tạo mới. Điều này tránh được việc tạo đơn trùng khi API lỗi hoặc email gửi lại.

Phạm vi cửa hàng: Mỗi cửa hàng Etsy có API key riêng. Hệ thống chỉ lấy đơn từ cửa hàng đã authorization. Nếu cửa hàng mới muốn tham gia → BA lead phải thêm OAuth key vào hệ thống, rồi hệ thống bắt đầu pull đơn của cửa hàng đó.

ETiêu chí thành công

  • Thời gian Etsy → Odoo
    ≤ 5 phút (Cron chạy 5 phút/lần, trong 95% lần lấy được dữ liệu)
  • Tỉ lệ ingest thành công
    ≥ 99% đơn parse đúng (hôm nay: 99.2%)
  • Tỉ lệ auto-match khách
    ≥ 90% khách match tự động, không cần BA duyệt (hôm nay: 91%)
  • Công suất
    50–100 đơn/ngày, API time < 5 giây mỗi lần
  • Failover email
    ≤ 30 phút từ lúc API hỏng 3 lần đến khi email parser bắt đầu
