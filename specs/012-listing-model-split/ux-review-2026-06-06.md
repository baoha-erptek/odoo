# UX Review Report: multichannel.listing Form (P-LIST-UX-REVIEW)

**Date**: 2026-06-06
**Status**: Phase 1 audit; 5/7 Wave-2 slices shipped
**Baseline**: `product.template` form (Odoo CE)
**Stakeholder**: Marketing operator, JaHandmadeArt, ~50 listings/day, prior Etsy Shop Manager user
**Goal**: Catch layout/labels/flow friction BEFORE P-LIST-ATTRIBUTES, P-LIST-ATTR-CONFIG, P-LIST-SHOP-BULK ship
**Companion mockup**: `ux-review-2026-06-06.html`

## Current Form Baseline

The form shipped by P-LIST-MODEL and extended by P-LIST-VIDEO, P-LIST-CATEGORY, P-LIST-SHIPPING, P-LIST-HOW-ITS-MADE has:

- **Header**: statusbar (draft / ready / published / error)
- **Sheet**: avatar + h1 title (editable) + Scope group (product, channel, shop, sequence) + External group (external_ref, last_synced_at)
- **Notebook tabs**: Marketing copy | Video | Etsy (5 fields: taxonomy, shipping profile, who_made, when_made, is_supply)

## Top 5 Friction Findings

### 1. CRITICAL: Missing "Open in Etsy Shop Manager" Call-to-Action

| | |
|---|---|
| **Severity** | High impact, high frequency |
| **Evidence** | Etsy Shop Manager surface shows a live "Go to Etsy" link on every listing. Operators expect parity. |
| **Current state** | `multichannel.listing.external_ref` is RO field buried in "External" group; no CTA. |
| **Impact** | Operator manually constructs Etsy URL or opens Shop Manager separately. ~5 clicks/listing × 50/day = 250 wasted clicks daily. |
| **Recommendation** | Add a green action button ("Open in Etsy Shop Manager") visible only when `state='published'` AND `external_ref` is not null. Place near title/avatar for prominence. **10-line XML change on `multichannel_hub_core.view_multichannel_listing_form`** + 5 lines JS to construct URL from `shop_ref` + `external_ref`. |
| **Slice** | Retroactive to P-LIST-MODEL |

### 2. HIGH: Tab organization does not align to Etsy's publish flow

| | |
|---|---|
| **Severity** | Medium friction; compounds with fatigue on high-volume days |
| **Evidence** | Etsy Shop Manager enforces "Listing Basics → Variations → Who Made → Shipping → Tax". Odoo current: "Marketing copy → Video → Etsy" (mixed concerns). |
| **Impact** | Operator switches from Etsy to Odoo; mental context doesn't transfer. P-LIST-ATTRIBUTES will add a 6th tab (attribute mapping), and operator won't know where to look. |
| **Recommendation** | Reorganize to **"Listing Basics" (title + description) \| "Photos & Video" \| "How It's Made" (who_made, when_made, is_supply) \| "Shipping & Variations" (shipping profile + attribute mapping when it ships)**. Mirrors Etsy's cognition, keeps related fields together. |
| **Slice** | Apply during P-LIST-ATTRIBUTES |

### 3. HIGH: Dropdown fields (taxonomy, shipping) lack cache-sync visibility

| | |
|---|---|
| **Severity** | Medium operator frustration; support escalation risk |
| **Evidence** | Taxonomy + shipping profile dropdowns read from cron-synced cache. No UI signal of when cache was last refreshed or if a manual refresh is possible. |
| **Impact** | Operator adds a new shipping profile on Etsy, but Odoo dropdown hasn't updated (cron runs hourly). Operator thinks Odoo is broken → support ticket. |
| **Recommendation** | Add a `sync-indicator` below each M2O dropdown: "Last synced 30 min ago" + a "Refresh now" button that triggers a manual `cron_sync_etsy_*` call. Cost: 2 fields per cache model (`last_synced_at`, computed `is_stale`) + 1 server action per slice. |
| **Slice** | Apply to P-LIST-CATEGORY + P-LIST-SHIPPING (retroactive) |

### 4. HIGH: Fallback chain is unclear when P-LIST-ATTRIBUTES ships

| | |
|---|---|
| **Severity** | Low frequency, high error cost (wrong variant shipped to Etsy) |
| **Evidence** | Spec 012 US6 defines a 3-tier fallback for attribute mapping: listing override → shop default → global `product.attribute.x_etsy_property_id`. When all three exist, operator doesn't know which wins. |
| **Impact** | Edge-case products (e.g., "Size" maps differently for one listing) get wrong variant combo published to Etsy. |
| **Recommendation** | Add a blue help box on attribute mapping tab: "Priority: Listing override → Shop default → Product global. Leave empty to use the next tier." Also: Phase 2 ORM tests covering all 3 tiers (not just happy path). |
| **Slice** | Apply during P-LIST-ATTRIBUTES |

### 5. MEDIUM: "Scope" group is operational noise for Marketing operators

| | |
|---|---|
| **Severity** | Low friction; clutter |
| **Evidence** | Fields in Scope group (product_tmpl_id, channel_id, shop_ref, sequence) are readonly, informational, or internal. |
| **Impact** | Form feels busy; operator scrolls past irrelevant fields. |
| **Recommendation** | Hide Scope group behind a collapsible "Advanced settings" section. BA users (who care about shop_ref) can expand when needed. Wrap in `<details>` or `<group string="Advanced" attrs="{'invisible': ...}">` in mhc view. |
| **Slice** | Retroactive to P-LIST-MODEL |

## Recommendations by Remaining Slice

### P-LIST-ATTRIBUTES (T501–T507)

- **Implement HIGH #4 fix**: 3-tier fallback explanation + Phase 2 ORM tests covering all paths.
- **Implement HIGH #2 fix**: Reorganize tabs so attribute mapping lives in "Shipping & Variations" tab (not a new 6th tab).
- **Add**: Phase 2 test validating: (a) listing override exists → use it, (b) override empty + shop default exists → use shop, (c) both empty → use global.

### P-LIST-ATTR-CONFIG (T601–T606)

- **Implement HIGH #4 fix** (shop-level): Help text on shop config form: "These defaults apply when a listing doesn't override. Listings always win over shop defaults."
- **Add**: Document whether this is manual config only (Admin per shop) or autopopulated from a config import similar to taxonomy/shipping sync.

### P-LIST-SHOP-BULK (T701–T706)

- **Implement HIGH #2 fix**: Ensure Listings list view has a "Shop" filter/grouping so operators pre-filter before bulk edit opens. Pairs with Scope visibility (operator needs `shop_ref` to filter, so it shouldn't be hidden unconditionally).
- **Add**: Validation in server action that rejects bulk-edit if `state != 'draft'` (respect state machine). Test: bulk-edit on published listings → expect silent filter OR explicit "X listings already published, cannot re-edit."
- **Add**: Help text on bulk-edit form: "You are marking X listings ready for publication. BA will review before they go live on Etsy."

## Small Fixes to Apply Retroactively (to shipped 5 slices)

### Fix R1 — Add "Open in Etsy" CTA

- **Affected slice**: P-LIST-MODEL (already shipped)
- **Change**: `multichannel_hub_core/views/multichannel_listing_views.xml` — add action button in form header/avatar area.
- **Pattern** (Odoo 19 syntax):
  ```xml
  <button name="action_open_in_etsy" type="object"
          string="Open in Etsy Shop Manager"
          class="btn btn-primary"
          invisible="state != 'published' or not external_ref"/>
  ```
  Plus a server action method on `multichannel.listing` that returns `{'type': 'ir.actions.act_url', 'url': 'https://www.etsy.com/your/shops/%s/tools/listings/%s' % (self.shop_ref, self.external_ref)}`.
- **Cost**: 15 lines XML + 5 lines Python; no DB change.

### Fix R2 — Add state-machine context help box

- **Affected slice**: P-LIST-MODEL
- **Change**: Add a blue info box below the statusbar explaining "Draft → Ready (BA approval) → Published → (editable for sync)".
- **Cost**: 3 lines XML; zero logic.

### Fix R3 — Add readonly lock when state != draft (CRITICAL safety)

- **Affected slice**: P-LIST-MODEL
- **Change**: Add `readonly="state != 'draft'"` to editable field groups in the form.
- **Pattern** (Odoo 19 syntax):
  ```xml
  <group string="Marketing copy" name="marketing"
         readonly="state != 'draft'">
      <field name="description"/>
  </group>
  ```
- **Cost**: 1 attr per editable group; no logic.
- **Impact**: CRITICAL safety — operators can no longer accidentally edit published listings.
- **Test**: Phase 2 ORM — create listing, publish, attempt write → expect AccessError or silent no-op.

### Fix R4 — Sync indicators on taxonomy/shipping dropdowns

- **Affected slices**: P-LIST-CATEGORY, P-LIST-SHIPPING (retroactive)
- **Change**: Add a `<div class="o_form_sheet_hint">` below each M2O dropdown with `last_synced_at` + "Refresh now" button.
- **Cost**: 10 lines XML per dropdown + 2 server actions (one per cache model) that trigger `_cron_sync_*`.

## Operator Voice — BA / Marketing Alignment

From a Marketing operator's perspective (50 listings/day, Etsy Shop Manager vet):

- **Odoo form feels good** after R1 (Open in Etsy link) and HIGH #2 (tab reorg) land. Mental model switches smoothly: "I enter here what I want on Etsy, then I can jump to Etsy to verify."
- **The fallback chain (#4) is scary** until help text arrives — operators will mis-configure without it.
- **The state machine (R3, readonly) is critical safety** — Marketing doesn't want to accidentally edit a listing after it's published and Etsy has moved on.
- **Shop filter (#2, in SHOP-BULK) is essential**. Editing 50 listings/day means I need to batch-filter by shop *before* opening the form.
